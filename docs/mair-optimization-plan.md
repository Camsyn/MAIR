## 第一阶段：为 #1 找一个值得做的点

**本轮补测。** 用 Clang 源码覆盖率编译 SQLite 3.33.0，`-O2`，沿用 [e2e 的 SQLite 宏](../test-e2e/sqlite3/CMakeLists.txt#L15)。读 `constructAutomaticIndex` 的 `if (extraCols & MASKBIT(i))` 真、假边，而不是看整个函数有没有被调用。SQLite 功能 oracle，以及四份仓库 SQL 各经独立的内存数据库执行，五次的计数均为 **真 0 / 假 0**。另用没有显式索引的两表连接作为正对照：**真 3 / 假 1**，两条数组写各执行三次。这是查询规划时构造索引描述的成本，不应乘上 SQL 扫描的行数。未用带覆盖率的二进制计时，也未将源码计数当成最终 MAIR 命中数。

这个例子还有两道门槛：进入循环时 `n` 未必为零；历史 `-O2` IR 在命中块中分别 **load 两个基址**，不是天然在出口可用的同一个 SSA 值。不能为了收下这个例子而假定无别名、在出口重读一个指针，或放宽“只有一个递增点”。现有[窄下标回环合并](mair-loops.md#窄下标回环访问)处理的是每轮都走的窄递推，不为这里的条件计数提供证明。

**首版有技术正例，但没有热例。** 一个寄存器位图解码器把置位编号依次写入 `out[written++]`，循环内没有其他业务访存。在默认 `-O2` 下仍留下唯一写点和逐字节 ASan 检查，LPOC 拒绝原因是 `rej-nonaffine`。现状对 65,538 个合法掩码给出预期的写入顺序、个数和未写尾部；这不是对尚未实现的变换做过回归。SCEV 虽不知精确轮数，但给出最多 32 次回边，足以证明从零、每轮至多加一的 32 位游标不回绕。这个上界**只用于证明**，实际长度仍取终值，不能用 33 代替。

1. **机会核查已完成，停止本期 #1 投入。** 7-Zip BZip2 编码器的 `mtfBuf[numInUse++]` 在固定文本的 22 个块各追加 20 次、固定二进制的 21 个块各追加 256 次，共 5,816 次，仍有逐写 ASan 检查。但在 MAIR 接手前正常 `-O2` 已经生成两处条件写和两处 `+1`，且两个副本在每块都执行，不能证明唯一递增点。另两处分别是打包字的读改写和当前配置未编译的分支。与 SQLite 的限定负结果合看，不启动原型、不放宽规则，也不推断其他项目无机会。后两步以找到符合规则的真实热点并获批为前提。[复跑与逐块证据](../.archive/roe_partial_20261118_1722/subagent/spawn_evidence_task/review_20261118_1722.md)
2. **严格原型，约 3–5 人日，需另行批准。** 在 [LPOC](../src/instrumentation/MAIR/Transforms/LoopPeriodicObservationCombinePass.cpp#L753) 增加独立识别函数：只接单层循环、单个普通 ASan 写、稳定的循环外基址、单一 SSA `+1`、不命中保持原值。先从初值零、元素宽一字节做起；非零初值/更宽元素只有在真实命中需要且能证 `(end-start)*width` 不溢出时扩展。返回起点、最终游标、宽度和出口；独立改写函数复用 [现有提交路径](../src/instrumentation/MAIR/Transforms/LoopPeriodicObservationCombinePass.cpp#L898)。不新增计数器，不削弱原有仿射规则，不借 TSan 或组合模式充当正例。
3. **正确性验收。** 先写负例，再实现：第二个静态更新点、地址有洞、计数回绕、基址只在命中路径定义、多出口、barrier 均不变换。逐写必经[合法出口](../src/instrumentation/MAIR/Analysis/LoopAnalysis.cpp#L328)，零命中（含零迭代）不得检查输出或额外求值未定义地址。正例逐个比对写出的字节序列、未写尾部、返回值，并检查最终 IR 的业务写仍在循环、非空时恰有一个精确范围检查，输入读不变。默认 ASan 已有[延迟报告边界](mair-loops.md#数据相关的出口)；不把逐次首错顺序相同当成默认事实，也不顺带扩至 recover、调试模式或同步相关场景。

**实施前需陈确认的边界。** 现有 LPOC 允许某些诊断延后，但“输入读没有改”不保证原来应先报告的输出写不会被较晚的输入读抢先。首版只收观察窗口内 shadow 稳定、无其他可能抢先报告的源（或能证明它们不报告）的单写流。`__asan_storeN` 报整段宽度，不是原来的一字节；若此处要求保留原宽度或写前诊断，则不实施出口方案。零长度回调若不读 shadow 且参数在该路径合法，可满足零命中语义，不要求强行增加一个分支。

## 后续必做：#5 先证完整覆盖，不等 #4

**最小问题是删一次已经查过的动态写，不是先建通用求解器。** 在目标 PP 证明同一对象上 `delta = targetStart - witnessStart`，`0 ≤ delta ≤ witnessBytes - accessBytes`；先证两个长度已知、`accessBytes ≤ witnessBytes`，按地址空间的索引宽度无回绕解释差值。正例宽 1，最大偏移 63；改宽 2，上界降到 62，必须保留原检查。只接受 `Full`，任何无法证明的情况均不变换。

1. **限定见证与语义，约 1 人日。** 本次**新增的删查规则**仅由独立、非 recover 的 ASan 显式启用，不扩大共享 `contains` 对其他调用者的成功集。只收同一作用域、恒真、支配目标、无 barrier、单来源的普通检查；优化时就要能保证经后续两轮 ROE、移动、选择及最终发射后，见证仍在先，检查足迹不缩小。不能仅凭 PostDom、相同覆盖级别、预计会走内联或图中尚有节点就删。`__asan_memset` 受 [runtime 的 `replace_intrin`](../src/runtime/lib/asan/asan_interceptors_memintrinsics.cpp#L43) 控制：首版保留 `memset + (i & 63)` 作**区间证明正例、删查负例**。不变更原有常量覆盖规则，不引入运行时补查。
2. **接入查询，约 2–4 人日。** 先跑 [ROE 的现有快速包含](../src/instrumentation/MAIR/MAIRRegion.cpp#L250)；只对同基址、已知宽度的剩余候选复用 [OBE 的 SCEV 范围证明](../src/instrumentation/MAIR/Transforms/ObjectBoundsEliminationPass.cpp#L154)。见证可用性仍由 [ROE 分析](../src/instrumentation/MAIR/Analysis/RedundantObservationAnalysis.cpp#L29) 负责。跨 PP 优先；若同 PP 正例的见证在常量组、目标在符号组，需在[现有组间边界](../src/instrumentation/MAIR/Transforms/RedundantObservationEliminationPass.cpp#L138)定向连接，不能把全体 Observation 改成两两比较。先不用 SMT；不硬编码掩码，不把「对象可信」作为这个查询的前提。仅在第二类用例显示新增收益时扩展到按需 LVI。
3. **验收和承诺分开。** 图、最终独立 ASan IR、默认 runtime 三层验证。用掩码与非掩码的 `zext`/范围事实作正例；宽 2、负位移、不同基址、被跳过或被移除的见证、宽度未知、跨状态更新作负例。分别以独立 TSan、组合 XSan、ASan recover 自身基线对照目标地址、宽度与事件；组合路径并不替独立 TSan 执行这一轮 ROE。记录 SCEV 查询数、成功数及编译时间。正确性 MVP 是后续承诺；找不到可测热例便不默认开启，不把「做证明」等同于「必须申请默认启用」。

**首个后端验收例**选无条件、16 字节对齐且完整发射的普通 16 字节写，随后在条件分支中执行 `p[i & 15] = v`：有明确先后，也是两处不同的 PP；移除的只应是后一次写的检查。**剔除一个旧正例**：以当前 SQLite e2e 参数重编 `sqlite3_randomness`，覆及表的 `__asan_loadN(...,256)` 在混排循环**出口**，目标访问在循环**体内**；先前 16 条向量业务写并没有留下所需的前置整段检查。另一个 256 字节 `__asan_memset` 的目标是栈上的 `k`，不是该表。因此该实例不是本期“先查整段”的收益样本。

## 本轮实施：#4 部分覆盖

以先读 `[0,16)`、再条件读 `[8,24)` 为例：`covers` 返回 `Partial([8,16))`，后一次业务读仍读原来的 16 字节，只检查 `[16,24)`。旧的整条删除逻辑只接受 `Full`。首版要求两端都是原位置、恒真、来源唯一、至少 8 字节对齐的普通 load；见证宽 8 或 16，目标宽 16。只沿本层无屏障的单一 Dom 链找最近的见证，不接受仅有 PostDom、被删除或已经缩窄的见证。见证及残余检查都不能再移动、合并或删除。写、动态区间、带洞或需要多次检查的差集不处理。

**开关与诊断。** `mair-opt -passes='roe<partial>'` 可单独验证，`mair-opt -O3` 或 `-passes='default<O3>'` 启用末轮 ROE 的选项；普通 `roe`、`-O1` 不变。生产路径要求 `MAIR=1`、实际 Clang `-O3`、纯用户态 x86-64 ASan、默认静态 shadow 和非 recover。混合 sanitizer、非默认映射和强制回调等不启用；若函数按阈值动态选中回调，仍发射原地址的完整 16 字节回调。标准内联模式下错误路径始终报告原 load 的地址、读宽和源码位置。`-mair-stats` 中 `narrowed` 计图上的缩窄，不计为 `eliminated`，也不代表动态次数或耗时。[图级测试](../test/MAIR/TestCases/roe-partial.ll) · [实际 ASan 测试](../test/MAIR/TestCases/asan/mair-roe-partial.ll)

**本轮实际收益边界。** 两个定向函数以同一 Clang `-O3`、`default<O1>` 作为关闭 partial 的对照，最终汇编只改动各自的一条 `cmpw → cmpb`；查高半区用 shadow 地址加 1 的寻址位移，不额外计算应用地址。对 SQLite 3.33.0 主编译单元的 `MAIR=1 -asan -O3` 编译，`roe#2` 访问 39,473 个观测，完整删除 22 个，部分缩窄 **0 个**；固定功能 oracle 输出 `failures=0`。这里没有 SQLite 加速结论。

## 有条件重开的方向

- **A：只统计最终还要付钱的 guard。** 逐 PP、逐 reset、逐出口核对精确来源、可用 SSA、不回绕且不会引入新的 poison 分支；测试零次、嵌套重入、展开两路和向量余尾。与[已有同块免 guard 和 SSAUpdater](../src/instrumentation/MAIR/Materialization/MAIRMaterialization.cpp#L324)及普通 LLVM 后处理比较。若有热例且最终少一项循环内工作，先做局部物化实验（约 1–2 人日）；有多个独立消费者才讨论改 MAIR guard 类型。无热例不建 pass。
- **A 的筛选分母**：历史 SQLite IR 中直接使用 `mair.executed` 条件的分支有 37 处，分布在 18 个函数；不是 37 处优化机会。`sqlite3WhereBegin` 的相似计数从上一循环继承初值，不能用 `exitCount != 0`。若要保留入口值再比较，须重新计算寄存器活跃期的代价。
- **B：先判定是否真需要 MAIR。** 在[最终选择后、改 CFG 前](../src/instrumentation/llvm23/AddressSanitizer.cpp#L4608)规划；首版只取有实测 profile 的恒真 PP，不用原 load 的频率估算移动后的 guard 命中。对同一输入比较现状、全内联、全回调、混合，并在原生 ASan 上做同等混合对照；训练、复核输入分开。原生也能得到等效结果，或混合被某一现有模式在速度和体积两方面同时赶上，就不做 MAIR 专用策略。缺乏可信 profile 不建采集基础设施。先给证据 1–2 人日，不排生产开发。
- **#2 / #3 的重开顺序**：先有默认 `-O2` 下仍保留的合法真实热点，才做离线计时；实测有净收益才申请开发。#3 须为每个展开副本分别证明相位和尾部次数，不能给每路套同一个总数。#2 已有的 [LPOC 头部 TODO](../src/instrumentation/MAIR/Transforms/LoopPeriodicObservationCombinePass.h#L9) 不变；本计划不再分配工期。

## 合入门槛

- **对照统一。** 用同一修订、工具链、编译选项与运行时，一次只变一条规则；以 `MAIR=1` 默认 `-O2` 为主基线，原生 ASan 用于核对语义，`mair-opt -O1` 只验证图。现有流水线有[两轮 ROE](../src/instrumentation/MAIR/MAIRPasses.cpp#L120)，要在最终 IR/汇编重新计数，不能把两轮命中相加。保持 `-O0`、默认未覆盖的 sanitizer 和显式策略不因新规则变化。
- **正确性先行。** 相应的 [LPOC 单测](../src/instrumentation/MAIR/unittests/LoopPeriodicObservationCombinePassTest.cpp)、[ROE 单测](../src/instrumentation/MAIR/unittests/RedundantObservationEliminationPassTest.cpp)、`test/MAIR/TestCases` 正反例及 sanitizer 级回归均通过，再运行 `ninja -C build check-mair` 和固定 e2e oracle。图 verifier 不证明最终发射正确。任何额外误报、漏报或未批准的诊断差异均阻断合入。
- **收益可证伪。** 先做同基线对同基线的 A/A 测量确定噪声，再固定 CPU、输入、预热，至少 10 对交替顺序运行基线与候选；分别报告热点/端到端时间、`.text`、编译时间及成对差异区间。用相同输入重放，不比较两个自适应 fuzz 过程。时间改善须超出 A/A 噪声且 95% 成对区间不跨零；体积优化则预先约定可接受的时间退化界限。在默认大型 TU 上编译退化超出噪声须单列评审。未满足门槛就交付负结果，保留 TODO，不默认启用。
